Webex to Mac

webex-notifier

Native macOS notifications for Webex DMs & @mentions — no admin approval.
⚠ Problem Statement
Webex just doesn't alert you reliably — especially while you're in a meeting — nothing like Slack's notifications. This fixes that — the instant a DM or @mention lands, it pops up right in your Mac's notification center.
Three Steps and a Beer
🍏 macOS only ⏱ ~2 min setup 🔒 no shared secrets

1Requirements

  • A Mac with Terminal access — Apple Silicon or Intel, both work. No Python install needed beforehand.
  • Your own Webex/Cisco login. That's it — no shared secrets, no IT ticket.
✅ Nothing to install by hand. run.sh bootstraps uv via its official installer (a single prebuilt binary — no Homebrew, Rust, or Xcode toolchain needed) if it's missing, then uv creates the private virtual environment — fetching its own Python if needed — and installs the one dependency (requests). No pip install or brew install python3 required.

2Download the zip

Grab the package below — it's just source code, no secrets inside. Unzip it anywhere.

⬇ Download webex-notifier.zip

3Install

  1. In Terminal: cd webex-notifier (wherever you unzipped it)
  2. Run: ./run.sh
  3. That's it — the script executes everything below automatically, nothing to do manually except paste back the two values it asks for:
    • Register your own Webex Integration (~30 sec, one-time). Opens developer.webex.com/my-apps/new/integration and tells you to:
      • Name it anything, e.g. Webex Mac Alerts.
      • Icon: pick any, doesn't matter.
      • Redirect URI: exactly http://localhost:8734/
      • Scopes: check spark:messages_read, spark:rooms_read, spark:people_read
      • Click Add Integration.
      You'll land on a page showing a Client ID and Client Secret — press Enter in Terminal, then paste each one back when prompted. It's saved to ~/.webex_notifier/app_config.json on your machine and never asked for again.
    • Your Cisco/Webex login email — typed straight into Terminal when prompted.
    • Browser sign-in — opens Webex's own login page to authenticate as that email; a local listener on localhost:8734 catches the redirect and exchanges it for tokens automatically.
    • Watermark set to now — so only new activity from this point on triggers an alert, not your whole message history.
    • Cron job installed — a personal crontab entry that runs webex-notifier check every minute, logging to ~/.webex_notifier/monitor.log.
    • Test notification fired — a native macOS banner confirming notifications work.
    • Live check run once — checks right away for any real DMs/mentions instead of waiting for the first cron tick.
💡 No banner on the test notification? Open System Settings → Notifications → find "Script Editor" → turn on Allow Notifications and set style to Banners or Alerts (not None). Then run ./run.sh notify-test again.

Everyday commands

./run.sh statusShow auth + cron state
./run.sh doctorDiagnose and fix problems interactively
./run.sh checkRun one check right now (don't wait for cron)
./run.sh notify-testFire a one-off test notification
./run.sh cron-uninstallStop and remove the background check

Troubleshooting OAuth errors

  • "We've encountered an error. Try again later." — almost always a redirect URI mismatch. Re-open your integration at developer.webex.com/my-apps and confirm the Redirect URI is exactly http://localhost:8734/ (note the trailing slash), then save and retry.
  • "The requested scope is invalid." — go back to the integration's Scopes section and make sure all three are checked: spark:messages_read, spark:rooms_read, spark:people_read. Save, then retry.
Each person registers their own Webex Integration and keeps their own tokens under ~/.webex_notifier/ — nothing here is shared between colleagues, and there's nothing sensitive in this folder to protect when you pass it along.
